# Deploy to Render

[`render.yaml`](../../render.yaml) is a Render **Blueprint** that provisions the backend as a Docker
web service plus a managed PostgreSQL database and a persistent disk for uploads. The container runs
`alembic upgrade head` and binds uvicorn to Render's assigned `$PORT`.

## One-time setup

1. Push this repository to GitHub (already connected: `Kiwmoj/SkillBridgeAI`).
2. In Render: **New → Blueprint**, pick this repo, and apply. Render reads `render.yaml` and creates:
   - **skillbridge-api** — Docker web service built from `infrastructure/docker/Dockerfile`, health check `/health`.
   - **skillbridge-db** — free PostgreSQL; its connection string is injected as `DATABASE_URL`.
3. `JWT_SECRET` is generated by Render. To enable AI features, set `GEMINI_API_KEY` and `GEMINI_MODEL`
   on the service (they are `sync: false`, so they are never committed).

## Verify

- Open `https://<service>.onrender.com/` → the **web app** loads (sign-in screen with live backend status).
- Open `https://<service>.onrender.com/health` → `"database": "healthy"`, `"environment": "production"`,
  `"jwt_secret_configured": true`.
- Point the desktop **Backend address** at the HTTPS URL (HTTPS is required for non-loopback hosts) and
  use **Create account** to make a student account — or just use the hosted web app directly.

## Seed the admin and O*NET data (free plan has no Shell)

Render's free web service has no Shell/Job, so run the one-time setup from your own machine against the
database's **External Database URL** (Render → the `skillbridge-db` database → *Connections* → External):

```powershell
$env:DATABASE_URL = "<external database url from Render>"
.\.venv\Scripts\python.exe -m apps.backend.cli.create_admin --email you@example.com
.\.venv\Scripts\python.exe -m apps.backend.cli.load_onet data\onet\raw\db_31_0_csv.zip
Remove-Item Env:\DATABASE_URL
```

The CLIs use the same configuration as the server, so this writes straight into the hosted database.
(`psycopg` is already installed from `requirements.txt`.) On a paid instance you can instead open the
service **Shell** and run the same two commands there.

## Notes and limits

- Keep **one instance**: the rate limiter and the O*NET import guard are in-process.
- **Free plan uploads are ephemeral** — Render free web services cannot mount a persistent disk, so
  `UPLOAD_DIR=/app/uploads` is cleared on restart/redeploy. For durable portfolio images, upgrade the
  service to a paid plan and add a disk (mount it and set `UPLOAD_DIR` to the mount path).
- Render's free web service sleeps when idle; the first request after a sleep is slow, and the free
  PostgreSQL plan expires after 90 days — use a paid plan for anything lasting.
- No deployment has been performed from this repository; verify the deployed health check before
  relying on it. The same blueprint approach applies to Railway (see [railway.md](railway.md)).
